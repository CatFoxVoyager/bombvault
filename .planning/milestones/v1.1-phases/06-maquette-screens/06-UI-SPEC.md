## Design System

| Property | Value |
|----------|-------|
| Tool | none — hand-rolled (project constraint: no UI kit; continues PRIM-01's precedent) |
| Preset | not applicable |
| Component library | none — house components only; new primitives in `web/src/components/mobile/` (BottomSheet precedent) |

| Font | system-ui stack (existing body font-family); `ui-monospace` (`font-mono`) for snapshot ids, host paths, log timestamps; `tabular-nums` for every count/stat/duration |

In-page adaptation is CSS-only (`max-md:` variants) wherever possible. No second page tree.

## Spacing Scale

Declared values (multiples of 4 only — Tailwind's existing scale, no new tokens):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px (`gap-1`) | icon-to-label gaps inside rows |
| sm | 8px (`gap-2`, `p-2`) | in-card element spacing, chip padding |
| lg | 16px (`p-4`, `gap-4`) | card padding, gaps between cards, sheet internals |
| xl | 24px (`p-6`, `gap-6`) | `main` padding on desktop (unchanged); mobile `main` padding becomes `p-4 md:p-6` (see below) |
| 2xl | 32px | sparse layout gaps |
| 3xl | 40px (`gap-10`) | PAGE_SHELL desktop rhythm — becomes `gap-6 md:gap-10` on the three maquette pages |

**Phase 6 scale decision** (resolves 05-UI-REVIEW minor finding 4): new Phase 6 code uses the
8/16 stops ONLY. No new 12px values (`gap-3`/`px-3`) in any Phase 6 file.

**Per-page responsive rhythm lands HERE** (explicitly deferred from Phase 5): the three maquette
pages (Dashboard, Containers, Files) move to `gap-6 md:gap-10` on their PAGE_SHELL root, and
`Layout.tsx`'s `main` moves to `p-4 md:p-6`. Desktop rendering is unchanged by construction
(`md:` values are today's values).

Exceptions (structural dimensions, not spacing tokens):

| Dimension | Value | Why |
|-----------|-------|-----|
| Touch-target floor | ≥44px on every interactive control below the breakpoint | VERIFY-04, SCRN-03 |
| Tree row height (touch mode) | ≥44px `min-h-[2.75rem]` per treeitem row (desktop keeps `min-h-8`/`min-h-7`) | SCRN-03 full-row targets (D-02) |
| Chevron hit zone (touch mode) | ≥44×44px dedicated right-aligned zone, never overlapping the check hit area | D-02 |
| BottomSheet close button | ≥44px hit box (bump from today's ~40px `p-2`) | absorbs 05-UI-REVIEW finding 6; PRIM-03 reuse blocker |
| Sticky action bars | content row ~56px + top hairline; no bottom safe-area padding (the BottomNav below `main` owns the inset) | D-03, D-06; sticky-in-flow, never `position:fixed` |
| BottomSheet (run-detail variant) | full-height `h-dvh` panel instead of `max-h-[85dvh]` | D-05 full-screen sheet |
| Safe-area insets | `env(safe-area-inset-*)` custom properties only; sheet side padding becomes `max(1rem, var(--safe-area-left/right))` | absorbs 05-UI-REVIEW finding 1 (SHELL-04) |

## Frozen-API Data Adaptations (load-bearing — read before planning SCRN-05)

Two maquette elements have NO source in the frozen data model. The `Run` record
(`internal/store/runs.go:12-32` mirrored at `web/src/lib/api.ts:341`) carries only:
id, targetId, kind, status, startedAt, finishedAt, snapshotId, bytes, error, acknowledged,
target, domain, groupId. `progress.ts` events carry key/phase/percent/active/startedAt/
snapshotIndex/snapshotTotal. There are NO per-file new/changed/unchanged counts and NO
per-file exclusion log lines anywhere on the wire, and this milestone may not change that.

**Resolution (auto-mode decision, documented per the milestone contract):**

| Maquette element | Contracted substitute (honest, frozen-API-fed) |
|------------------|------------------------------------------------|
| "new / changed / unchanged" stat triad | Three tabular-numeral tiles fed by fields that DO exist: **Data volume** (`humanBytes(run.bytes)`, `lib/forecast` formatter) · **Duration** (`formatDuration(finishedAt − startedAt)`) · **Snapshot** (mono `run.snapshotId.slice(0,8)`, full id as `title`). The header line carries status + completion time (`formatTs(finishedAt)`) |
| "excluded tmp (unticked) / skipped cache/ (CACHEDIR.TAG)" per-file log lines | The run activity log renders the EXISTING `buildLogLines` output for the run (same lib the desktop ActivityLog uses — reuse, no duplication): mono timestamps, run-level outcomes, reasons in the reader's language (`runReason`). The unticked / CACHEDIR.TAG attributions live where the truth lives today: the selection surfaces (`folders.previewPaths`, `folders.cachedirToggle`, the per-root exclusions disclosure) |

Never fabricate numbers (repo honesty culture); never break the freeze. The per-file triad and
per-file exclusion attributions are recorded here as a **v2 data candidate** (they need a
`runs` schema extension, i.e. an API-bearing milestone). The phase plan must carry this
substitution as a stated deviation against SCRN-05's verbatim wording.

### SCRN-03 — Touch selection tree (the phase's hardest work; D-01/D-02/D-03)

The ONE `SelectionTree` gains an interaction-mode prop (default `"pointer"` — desktop byte-identical,
existing vitest behavior suite untouched and green). In `"touch"` mode:

- **APG state model byte-identical**: `role="tree"`/`treeitem`/`group`, `aria-checked`
  true/mixed/false, roving tabindex, Space-through-`onToggle`, cascade semantics, serialized
  save queue wiring — ZERO changes to state logic. Only the interaction layer differs.
- **Hit semantics (D-02)**: tapping anywhere on the row toggles the check; the chevron is a
  dedicated ≥44×44px right-aligned zone for expand/collapse — the two gestures never share a
  hit area (desktop today inverts this: row click expands, checkbox toggles). The chevron zone
  carries an `aria-label` naming the row and the action ("{path} expand/collapse" class) — it
  is never an unlabeled icon-only control (checker dimension-2 recommendation, folded in).
  `touch-action: manipulation` on rows (kill double-tap-zoom). No hover-dependent styling in
  touch mode.
- **Rows**: ≥44px `min-h-[2.75rem]`, full-row target, labels at the 14px body register;
  EXCLUDED (and unreachable) rows muted (`text-carbon-textMuted` — existing tone rule,
  `SelectionTree.tsx:455-460`); mono `break-all` + `title` for long paths (house pattern,
  unchanged).
- **Notice rows** (loading / error+retry / empty / truncated / blocked) keep their
  presentation-wrapped shapes and copy verbatim; the retry Button becomes a ≥44px touch target
  in touch mode.
- **CACHEDIR.TAG toggle** renders with its plain-language line + InfoBubble in the action bar's
  second row (D-03) rather than per-root sub-rows ONLY — per-root sub-rows remain (state lives
  there); the bar carries the plain-language line `folders.cachedirToggle` + `folders.cachedirScope` bubble.
- **Save action bar (D-03)**: `sticky bottom-0` inside the scroller's flow (same discipline as
  the bottom bar — never `position:fixed`), `bg-carbon-sidebar` + top hairline; row 1 = live
  `folders.handedToRestic` count (12px, tabular) + `accentSoft` ticked chip; row 2 = Save
  button (filled accent, ≥44px). **Save semantics — byte-identical contract**: toggles keep
  live-saving through the ONE serialized queue exactly as desktop (no mobile buffer, no second
  save path); the Save press flushes the queue (drains any pending attempt), shows its busy
  state while a drain is in flight, and reports `folders.saved` success toast — a failed flush
  toasts AND shakes (house rule). PITFALLS:347 (pending/dirty indication) is covered by the
  existing rowBusy spinner treatment visible in the count row while `inFlight`.
- The tree's desktop height cap (`h-[clamp(12rem,55vh,32rem)]`, `SelectionTree.tsx:702`)
  becomes full available height in the stacked container detail (touch mode) — the detail view
  owns the scroll; the tree scrolls within it.
- E2E: touch-mode assertions via bounding boxes (row ≥44px, chevron zone ≥44×44, check/chevron
  hit separation); the vitest tree suite keeps passing unchanged.
