# Plan 260914-p9a — Une carte « Apparence » unique dans Settings (D-11)

## Contexte

Verdict device D-11 (2026-09-14, consigné dans 08-UAT.md) : l'onglet Général de Settings porte
9 cartes (`Domains`, `Language`, `Theme`, `Corners`, `Animations`, `Platform`, `Labels`,
`Colors`, `Quiet toasts`), scroll ~2300 CSS px, stamps rouges jugés trop lourds sur mobile.
Aucun déphasage de rendu (device = build local 390px).

Décision user (AskUserQuestion, 2026-09-14, actée — non rouvrable) : « Regrouper — une carte
"Apparence" unique : Thème, Coins, Animations, Plateforme, Couleurs, Labels en sous-sections

partagé, desktop intact. » « Desktop intact » = design system et look desktop non dégradés ;
la page Settings desktop est réorganisée elle aussi (même IA partout), pas de DOM desktop figé.

Faits vérifiés sur l'arbre à la planification (à ne pas redécouvrir — re-sonder les numéros de
ligne à l'exécution, ils peuvent avoir glissé) :

- L'onglet General vit dans `web/src/pages/Settings.tsx` (5339 lignes), une condition
  `{tab === "general" && …}` par carte (jamais de Fragment englobant — commentaire 4763-4768).
  Ordre réel des 9 cartes : Domains (`:3100`), LanguageCard (`:4730`, composant importé),
  ThemeCard (`:4740`, composant importé), Shape/Corners (`:4831-4855`), Motion/Animations
  (`:4881-4902`), Platform (`:4918-4937`), Labels (fragment `:4939-4980`), Colors (IIFE

  **Corners = `settings.shape`**, **Animations = `settings.motion`** (en : `"Corners"`/`"Animations"`,
  i18n.ts `:913`/`:923`).
- Le bloc commentaire 4742-4769 (« GENERAL — Appearance ») raconte l'histoire inverse : une
  carte umbrella `settings.appearance` a été splittée en quatre lors d'une passe live-review,
  puis accent+rainbow re-fusionnés en Colors ; la clé `settings.appearance` a été **retirée de
  toutes les locales** (« stays removed … rather than kept as a dead key »). Ce bloc est FAUX
  deux fois après la fusion → à réécrire (Task 2). Idem le commentaire i18n.ts `:877-887`.
- **Précédent exact de la fusion** : la carte Colors est elle-même une fusion accent+rainbow —
  `AccentCard` (« returns just its own body (no Card wrapper of its own) », commentaire
  `:4985-4986`) composée dans la Card Colors. ThemeCard suit le même traitement.
- `web/src/pages/settings/ThemeCard.tsx` : rend sa PROPRE `<Card title={t("settings.theme")}
  hueIndex={hueIndex}>` (`:126`) autour d'un seul `Selector` (`variant="well" equalWidth
  size="lg"`, glyphes soleil/lune). Fichier dans `pages/settings/`, PAS dans `components/` —
  le retoucher n'enfreint pas la contrainte « zéro composant partagé ».
- Pattern sous-titre (carte Labels, `:4953-4955`) : `<span className="text-xs
  text-carbon-textSub">{t(…)}</span>`. `InfoBubble` est déjà importé dans Settings.tsx (`:24`),
  usages inline en page body à `:755` et `:3062` — un span + bulle sur une rangée flex est dans
  les patterns de la page.
- `nextHue()` est un `hueSeq++` évalué en ordre JSX ; la fusion retire 5 appels (theme, shape,
  motion, platform, labels) et n'en garde qu'UN (la carte Apparence) — l'auto-correction des
  cartes suivantes (Quiet toasts, onglets system/storage…) est déjà documentée (`:5002-5011`).
  Retirer les appels morts, ne jamais en laisser un sans rendu.
- Clés i18n des six titres : `settings.theme` (pas de hint), `settings.shape`+`settings.shapeHint`,
  `settings.motion`+`settings.motionHint`, `settings.platform`+`settings.platformHint`,
  `settings.labels`+`settings.labelsHint`, `settings.colors` (pas de hint). Toutes RÉUTILISÉES
  telles quelles — rien à renommer, rien à supprimer.
- Pattern pré-seed 42 tables : commit `987a4d0b` (settings.platform*) — clé dans `en` inline
  `i18n.ts` à la position d'ordre d'écran + même position RELATIVE dans les 41 autres tables,
  pin dans `web/src/lib/i18n.preseed.test.ts` (const en exacte + non-vide partout + ban em/en
  dash). **42 tables** = `en` + `de` inline dans i18n.ts + 40 modules `web/src/lib/locales/*.ts`.
- Tests DOM : `Settings.platformCard.dom.test.tsx` (4 tests ; le test 1 asserte un `heading`
  au nom `en["settings.platform"]` `:158-163`) et `Settings.themeCard.dom.test.tsx` (rend

  « Appearance » ni les titres de cartes Settings (grep vérifié — seule occurrence : un

- Windows : les shims npm/npx perdent node du PATH (observation #13) — TOUTES les commandes

Choix du planner (décisions documentées, à suivre telles quelles) :

1. **Une seule nouvelle clé : `settings.appearance`. PAS de `settings.appearanceHint`.**
   Les quatre hints existants (shape/motion/platform/labels) restent vivants sur leurs
   sous-sections (voir décision 2) ; un hint umbrella ajouterait 42 copies pour une phrase
   redondante. Copy de référence : en `"Appearance"`, fr `"Apparence"`, de `"Erscheinungsbild"`,

   dash** (`—`, `–` interdits, testé).
2. **Sous-titre = span discret + InfoBubble quand la section a un hint.** Les quatre sections
   à hint portent leur bulle d'origine à côté du span (les clés hint restent ainsi vivantes —
   le gate orphans + « réutiliser telles quelles » l'exigent) ; Theme et Colors (jamais de
   hint) ont le span nu. Rangée : `<div className="flex items-center gap-1">` + span pattern
   Labels + `<InfoBubble tip={t("settings.shapeHint")} />`.
3. **ThemeCard passe en body-only** (précédent AccentCard) : wrapper Card supprimé, prop
   `hueIndex` retirée (elle n'alimentait que le heading), tout le reste (state, effet
   system-flip, glyphes, Selector) inchangé.
4. **web/dist n'est PAS committé** — le brief dit « commit web/dist avec le code » mais la
   config repo fait foi : `.gitignore:14-18` garde les artefacts de build ignorés, seul le
   placeholder `web/dist/index.html` est tracké, et la décision phase 8 dans STATE.md dit
   « restore the web/dist/index.html placeholder before committing ». On build pour vérifier,
   puis on restaure le placeholder. Écart au brief assumé et documenté ici.
5. Placement i18n : `settings.appearance` inséré **immédiatement avant `"settings.theme"`**
   dans chaque table (position relative identique partout, convention 987a4d0b — l'ordre
   d'écran place l'umbrella juste avant sa première sous-section).
