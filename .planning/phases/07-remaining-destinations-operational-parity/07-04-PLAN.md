<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GET settings/repos -> mobile editor forms | The API returns secrets as "" + has* flags; a mobile form that captured and echoed any secret value would break the write-only contract |
| mobile editor -> settings/peer/repo write endpoints | Editor submits cross into domain writes; a full-object PUT or wrong merge shape could clobber concurrent edits or resurrect deleted fields |
| restore trigger | The Config restore entry fires a real destructive restore; the sheet narrates the frozen guard chain but must not alter its behavior |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|----------|----------|-----------|----------|-------------|-----------------|
| T-07-11 | Information disclosure (secret echo) | Receiver APP_KEY + Fleet token editors | critical | mitigate | Write-only contract preserved via RevealInput + has* flags: blank input + Set badge, blank-on-save keeps, Clear-only removes; e2e asserts the rendered value attribute is empty and the PUT body omits/keeps correctly (acceptance criteria Task 2/3) |
| T-07-12 | Tampering (restore misuse) | Config restore sheet | high | mitigate | The guard chain renders read-only ABOVE an outcome-naming confirm (D-03); the confirm reuses the desktop copy; restore behavior itself is frozen in Recovery.tsx — the sheet only narrates and fires the same guarded call; useConfirm/ConfirmSheet carries the destructive tone |
| T-07-13 | Tampering (settings/peer clobber) | configEnabled toggle + editor saves | high | mitigate | All writes ride the existing chains — queueSettingsWrite + savedBaseline merge-only-changed-field for settings, the existing peer/repo save functions for editors; no captured full-object PUT anywhere in the plan (prohibition + acceptance criteria) |
| T-07-14 | Misrepresentation (reachability language) | Receiver/Fleet status rendering | medium | mitigate | Four-status text-labelled badges only; offsite-blue tokens are banned for reachability in this plan's prohibitions; e2e asserts no offsite class on reachability elements |
| T-07-15 | Tampering (desktop regression) | three double-gated pages | medium | mitigate | Desktop JSX stays rendered in max-md:hidden halves; existing Config.autosave + Fleet.peerCard dom tests keep passing; Task 3's dual-direction e2e asserts no mobile chrome at >=48rem on all three routes |
| T-07-SC | Tampering (supply chain) | npm installs | low | accept | Zero package installs this phase (locked decision; Package Legitimacy Audit table: none) |
</threat_model>
