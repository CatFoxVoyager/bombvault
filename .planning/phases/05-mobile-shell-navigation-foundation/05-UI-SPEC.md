# Phase 5 — UI Design Contract

> Visual and interaction contract for the mobile shell + navigation foundation.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> Sources: 05-CONTEXT.md (12 locked decisions), design bible `design/mobile/README.md` +
> maquettes @0b64c7df, REQUIREMENTS.md v1.1 (SHELL-01..07, PRIM-01, VERIFY-01),
> `.planning/research/SUMMARY.md`, and direct inspection of `web/src/` (Layout.tsx,
> Sidebar.tsx, index.css, pageShell.ts, i18n.ts, eslint.config.js).
>
> Scope guard: this phase ships the STRUCTURAL shell in the shared carbon language.
> Platform-adaptive polish (M3 navpill, FAB, HIG large title) is PLAT-01 / Phase 7.
> Per-page mobile content (maquette screens) is Phase 6+. Desktop above 48rem is UNTOUCHED.

## Design System

| Property | Value |
|----------|-------|
| Tool | none — hand-rolled (project constraint: no UI kit; REQUIREMENTS PRIM-01 mandates a hand-rolled bottom sheet) |
| Preset | not applicable |
| Component library | none — house components only (`web/src/components/`), new mobile chrome in `web/src/components/mobile/` |
| Icon library | in-repo `web/src/components/navGlyphs.tsx` (Streamline free Core Solid family, one-icon-family rule #178/[202]); the "More" trigger adds ONE new ellipsis-class glyph to this same generator |
| Font | system-ui stack (existing `body` font-family: `system-ui, -apple-system, "Segoe UI", Roboto, sans-serif`); `ui-monospace` for snapshot ids/counts; tabular numerals (`font-variant-numeric: tabular-nums`) for any count |

Breakpoint (the ONE quarantine number): Tailwind `md:` = 48rem. The single JS media-query
literal `DESKTOP_QUERY = "(min-width: 48rem)"` lives in new `web/src/lib/useMediaQuery.ts`,
consumed ONLY by `Layout.tsx`, and is pinned to the CSS `md:` boundary by a guard test
(locked decision, 05-CONTEXT.md). All in-page adaptation is CSS-only (`max-md:` variants) —
never a second page tree.

## Spacing Scale

Declared values (multiples of 4 only — Tailwind's existing scale, no new tokens):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px (`gap-1`) | icon-to-label gap inside a bar item |
| sm | 8px (`gap-2`, `p-2`) | compact element spacing, bar horizontal padding |
| md | 12px | sheet row vertical padding |
| lg | 16px (`p-4`) | sheet side padding, default element spacing |
| xl | 24px (`p-6`, `gap-6`) | `main` padding (unchanged), section spacing |
| 2xl | 32px | layout gaps inside the sheet |
| 3xl | 40px (`gap-10`) | PAGE_SHELL rhythm — UNCHANGED this phase (desktop rhythm untouched; per-page responsive rhythm is Phase 6+) |

Exceptions (structural dimensions, not spacing tokens):

| Dimension | Value | Why |
|-----------|-------|-----|
| Touch-target floor | ≥44px on every interactive control below the breakpoint | SHELL-02, VERIFY-04 |
| Bottom bar content height | 56px (`h-14`), plus bottom safe-area inset padding | bar stays visible in `svh` terms; maquette nav bars are 56–76px platform variants |
| More sheet row height | ≥52px (`min-h-[3.25rem]`) | maquette iOS list cell `min-height: 52px`; comfortably over the 44px floor |
| Bottom sheet max height | `85dvh` | sheet never swallows the whole screen; content scrolls inside |
| Safe-area insets | `env(safe-area-inset-*)` via CSS custom properties | variable, env-driven — never a fixed value (SHELL-04) |

## Typography

Reuses the existing type tokens (`web/src/index.css`) — no new sizes:

| Role | Size | Weight | Line Height | Token |
|------|------|--------|-------------|-------|
| Heading | 20px | 600 | 1.2 | `--text-heading` (text-heading) |
| Body | 14px | 400 | 1.5 | `--text-body` (text-body) |
| Label/meta | 12px | 400 | 1.45 | `--text-dense` (text-dense) |
| Nav caption | 11px | 400 rest, 600 active | 1.3 | `--text-caption` (text-caption) — bottom-bar labels + More trigger label |

Weights: exactly 2 for all NEW code — regular 400 and semibold 600. (Weight 500 exists only
inside the pre-existing `.glim-btn` engine class; do not introduce new 500s.)

Exception (SHELL-07, load-bearing): login inputs render ≥16px EFFECTIVE font below the
breakpoint (e.g. `max-md:text-base` on the password/code fields in `Login.tsx`). iOS zooms
any focused input under 16px — this overrides the 14px body token on exactly those two
fields, mobile only. Desktop login rendering is unchanged.

## Color

All semantic tokens from `web/src/index.css`. The design bible's hex values are the token
DEFINITIONS — never hard-coded in components (VERIFY-05). Both themes verified.

| Role | Token | Value (dark / light) | Usage |
|------|-------|----------------------|-------|
| Dominant (60%) | `--carbon-bg` | #161616 / #f4f4f4 | app background (`bg-carbon-background`), already on Layout root |
| Secondary (30%) | `--carbon-surface` + `--carbon-sidebar` | #262626 / #ffffff | cards + More sheet panel = `carbon-surface`; bottom bar = `carbon-sidebar` (the SAME token the desktop rail reads — one nav-surface token, theme-reactive) |
| Accent (10%) | `--accent` / `--accentText` / `--accentSoft` / `--accentContrast` | #FCC419 family | see reserved list below |
| Destructive | `--status-fail-*` | #ff8389 family (dark) | NOT used by any Phase 5 control — reserved for four-status badges (Phase 6+) |

Ink rules (house law, light-theme load-bearing):

- Accent-colored TEXT/ICONS always read `--accentText` (dark = the raw #FCC419 look of the
  bible; light = #7a5c00, because raw #FCC419 on the light `--carbon-sidebar` #ffffff
  measures ~1.6:1 — the exact failure `--accent-text` was created to fix, index.css Task 7).
- Ink ON a solid accent fill is always `--accentContrast` (#161616) — NEVER white (bible
  rule: "on-accent ink never white").
- Status colors live on Badges/chips only, never on interactive controls (lint rule
  `bombvault/no-status-color-on-control`). Phase 5 chrome carries zero status color.

Accent reserved for (explicit list — nothing else):

1. Active bottom-bar item (icon + label tint, via `accentText`; optional `accentSoft` rounded
   backdrop behind the icon — this is the structural active language; the M3 navpill
   *indicator* treatment of it is Phase 7)
2. Active row inside the More sheet (`accentSoft` fill + `accentText` text — the established
   Badge `tone="active"` recipe)
3. Focus-visible rings (`--focus-ring`, existing base rule)
4. Checked/selected control states and genuine-activity indicators (existing convention;
   no new Phase 5 consumers)

Four-status rule: ok / fail / warn / neutral (+ offsite blue as DOMAIN identity, never a
fifth status hue) — inherited unchanged. Phase 5 adds no status surface.

## Copywriting Contract

Every string through `t()` from `useT()` (lint-enforced); em dashes banned; backend error
text shown verbatim. New keys go into `en` + `de` (inline in `web/src/lib/i18n.ts`), then
all 40 locale modules via `import.meta.glob` — the parity tests (`i18n.parity.test.ts` et al.)
enforce the rest. German/French chrome must fit 320–360px (bar labels ellipsize, never wrap).

| Element | Copy |
|---------|------|
| More trigger label | en "More" — NEW key `nav.more` (de "Mehr", fr "Plus" for reference; 42-locale parity via pipeline) |
| More sheet title | same key `nav.more` — the sheet is titled by its trigger, no second string |
| Destination labels | existing `nav.dashboard` / `nav.recovery` / `nav.containers` / `nav.vms` / `nav.flash` / `nav.files` / `nav.config` / `nav.receiver` / `nav.fleet` / `nav.settings` — reused verbatim from the shared nav registry, never re-authored |
| Sign-out | existing `auth.logout` — sheet bottom, muted, below a hairline separator (locked decision) |
| Empty state (More sheet, zero gated destinations enabled) | sheet still opens showing the separated sign-out row; if `authEnabled` is false too, the 5th slot is hidden entirely and the bar renders 4 items — an empty sheet never exists, so no empty-state copy is authored |
| Error state | none new — Phase 5 chrome performs no fetches; the nav registry is a pure synchronous derivation of already-loaded `Settings`. Backend error text (login, sign-out) shows verbatim per house rule |
| Destructive actions | sign-out only. Confirmation approach: NONE — fires immediately, matching desktop `SidebarSignOut` parity (sign-out is reversible by signing back in). Fail-tone destructive sheets are PRIM-03 / Phase 6 and MUST NOT debut here |
| Primary CTA | none in this phase — the shell has no data actions. "New backup" thumb-zone CTA is SCRN-01 / Phase 6 |

## Viewport & Shell Contract (SHELL-04/05/06, load-bearing)

| Concern | Contract |
|---------|----------|
| Root sizing | `Layout.tsx` root replaces `h-screen` with `h-dvh`; flex DIRECTION switches below the breakpoint (column: `main` then BottomNav; row: Sidebar then `main` above). `100vh` appears NOWHERE in the mobile shell |
| Bar in normal flow | BottomNav is a `shrink-0` flex SIBLING after `main` — never `position:fixed` (SHELL-02) |
| svh | static chrome that must stay visible (bottom bar) sizes against `svh` semantics; `dvh` only where tracking browser-chrome collapse is wanted (root). `main` remains the scroll container (`overflow-y-auto`) |
| Safe areas | `viewport-fit=cover` added to the existing viewport meta + new `:root` custom properties `--safe-area-top/right/bottom/left: max(env(safe-area-inset-*), 0px)`. BottomNav pads bottom by `--safe-area-bottom`; the More sheet pads all sides; login pads per insets. Desktop reports 0 and is unaffected |
| Android keyboard | `interactive-widget=resizes-content` appended to the viewport meta in `web/index.html`, BELOW the untouched FOUC script (SHELL-06) |
| iOS keyboard | ONE `focusin`/`visualViewport` mechanism, centralized at Layout level (locked decision) — never per-page. Contract: with the keyboard open, the active input is visible and the bottom bar never overlaps focused content |
| theme-color | `meta[name=theme-color]` added in `web/index.html`; `web/src/lib/theme.ts` updates its `content` on every theme application — #161616 dark / #f4f4f4 light (mirrors `--carbon-bg`; the two files carry a paired-change comment, the `widget.html` precedent). Fallback static content = dark value |
| Login (SHELL-07) | `authGate === "blocked"` already bypasses the shell (Layout returns `LoginPage` before Sidebar/`main`) — the bottom bar NEVER renders on login. Card stays centered; root `min-h-screen` → `min-h-dvh`; inputs ≥16px effective (see Typography exception); safe-area padding on the card container |
| Landscape | bottom bar stays at the bottom in BOTH orientations (locked decision — no landscape side rail) |
| Tap-on-active | tapping the already-active destination scrolls `main`'s scroller back to the top (SHELL-02 success criterion); mechanism lives in Layout, which owns the scroller |
| Focus discipline | sheet: focus-trapped (ConfirmDialog/`useConfirm` trap precedent), Escape closes, scrim click closes, focus returns to the trigger; bar items are `NavLink`s (native `aria-current`); `:focus-visible` rings via existing `--focus-ring` base rule |

## Interaction Contract

| Interaction | Behavior |
|-------------|----------|
| Tap bottom-bar item | navigates to the flat route (react-router `NavLink`); active item shows accent tint via `aria-current` styling |
| Tap ACTIVE bottom-bar item | no navigation; scrolls `main` back to top (SHELL-02) |
| Tap "More" | opens BottomSheet with remaining destinations in sidebar order; scrim + focus trap engage; backdrop inert |
| Tap destination in sheet | navigates + closes the sheet; if it was already the current route: close + scroll top |
| Tap sign-out | immediate logout + reload to login (desktop parity — no confirm) |
| Escape / scrim tap / close button | dismisses sheet; focus returns to the "More" trigger |
| Route lands on a More destination (/vms, /flash, ...) | no bar item is active; opening the sheet shows that row highlighted (`accentSoft`+`accentText`) so the user is never lost (locked decision) |
| Orientation change | bar remains bottom-docked in both orientations; insets re-read from `env()` automatically |
| Keyboard opens (Android) | `interactive-widget=resizes-content` shrinks the layout viewport; root `h-dvh` recomputes; bar stays visible below the input |
| Keyboard opens (iOS) | the one Layout-level visualViewport mechanism keeps the focused input visible; bar never painted over focused content |
| Hover | no hover-dependent affordance may be introduced in mobile chrome; Tailwind v4 already gates `hover:` behind `@media (hover: hover)` — desktop hover behavior untouched |
