Backups can be fetched out of another BombVault on a schedule, everything to do with another instance now lives on one page, and the permissions pass that runs after every backup was measured and cut from 584 ms to 53 ms.

## ✨ Added

- **Pull backups out of another BombVault** ([#227](https://github.com/junkerderprovinz/bombvault/issues/227)). Off-site replication pushes; this is the same idea with the ends swapped. Give BombVault another instance's repository address and that instance's APP_KEY, and this box fetches its snapshots into its own repository on a schedule you choose, without the far side configuring anything or even being awake.
- **The source repository is only ever read.** Three operations may reach it: opening it to check the key fits, listing its snapshots, and naming it as the source of the copy. It is never initialised, unlocked, pruned or written to, and a test checks which end each operation actually reached.
- **Each side keeps its own credentials.** The two repositories carry different passwords, since each instance derives its own from its own APP_KEY, and this box never lends the source its storage logins. An `rclone:` source is refused with the reason, because rclone would reach it using this instance's remotes.
- **A pull source carries its own settings**: which kind of backup it holds, its schedule, its download and upload limits, and the storage login for an `s3:`, `b2:` or password-protected `rest:` server. **Pull now** runs one immediately and **Test** checks the address and key without moving anything.
- **The source card reports the last result, not a fresh probe.** A pull is something that happened, so the card says whether it worked and how many snapshots arrived. A source that has been switched off says so instead of showing the tick it earned last week.
- **The README download row** now offers the documentation, the container image and the source archive as three marked buttons.

## 🎨 Design

- **Receiver, Fleet and Pull became three tabs of one page, called Instances.** They were three rail entries answering the same question, and two of them wore the same glyph. The lists behind them stay separate, because the same neighbouring box can need two of those entries at once.
- **Each tab still follows its own setting.** The rail entry appears once any of the three is on, the strip shows only the tabs that are on, and with one on there is no strip at all. The old `/receiver`, `/fleet` and `/pull` addresses still work and land on the right tab.
- **Dependent controls are absent rather than dimmed.** A control that cannot work yet is no longer shown greyed out inviting a click; where it must stay visible, it names the switch it is waiting for.
- **The password card lost its two session buttons.** Signing out is not part of changing a password.
- **Two-factor and passkey both say "Set up" and both carry a glyph.** They are the same kind of step and now read like it.
- **Six new animations, across all four motion levels**: a page tilt, a sheen along a progress bar, a press response, a hover lift, a spinner and a card entrance. The top level is called **Wild** and now moves like it.
- **Every motion level answers every animation with its own value**, checked by a guard, so a quieter level can no longer silently inherit the liveliest setting.

## ⚡ Improved

- **The permissions pass after a backup is about eleven times faster.** Measured against a real 123 GB repository of 8119 entries: it cost 584 ms, of which 93% was one `lstat` per entry, against a median backup run of 2 seconds. It now checks the 263 directories and looks inside only the ones that changed, which measured 53 ms on the same repository.
- **That pass no longer grows with the repository.** Its cost used to track the number of entries stored, which only ever increases, rather than the size of the run it follows. A pass that hits an error still repeats in full next time, and a complete sweep runs at least once a day.

## 🐛 Fixed

- **A copy between two repositories carried one password for both ends.** Every existing caller copies within one instance, where that is correct, so it never showed. Between two instances it would have failed in a way that reads as a mistyped APP_KEY for a key that was right.
- **Two read-only screens could write to somebody else's repository.** Listing snapshots clears a stale lock and retries, which is right for a repository this box owns. On a foreign one a lock usually means the other instance is backing up right now, and its lock files were being deleted.
- **A pull source could not be given its storage login.** The field existed everywhere except in the form, so an `s3:` or `b2:` source could be entered and never opened, and the refusal blamed the APP_KEY.
- **The dashboard's "next up" line showed the untranslated word "pull"** in every language. A guard now reads the scheduler's own job names and fails when one has no translation.
- **A themed helper class that named no colour token rendered no colour**, and nothing noticed until the element was looked at.
